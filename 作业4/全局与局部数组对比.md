# 九九乘法表纠错：全局与局部数组对比

两份 C 程序都检查81个表项，输出错误坐标 (1,1)、(2,3)、(4,5)、(6,6)、(8,8)。
2026-10-30 已在 DOSBox 中使用 Open Watcom 1.9 验证两版编译均为0警告、0错误，运行输出一致。

原始输出为 CHECKG.DIS、CHECKL.DIS；逐条中文注释在 CHECKG_注释.txt、CHECKL_注释.txt。

## 主要区别

| 项目 | checkg.c：全局数组 | checkl.c：普通局部数组 |
| --- | --- | --- |
| 定义位置 | main外 | main内，无static |
| 存储期 | 整个程序执行期间 | 本次main调用期间 |
| 本次实际数组位置 | 数据段，符号_tableData | 栈上，起点SS:[BP-0x56] |
| main预留局部空间 | SUB SP,6 | SUB SP,0x58，即88字节 |
| 初始化 | 初始数据已由可执行文件装入数据区 | 进入函数后从数据区模板复制81字节到栈 |
| 元素读取 | MOV AL,BYTE PTR _tableData[BX] | MOV AL,BYTE PTR -0x56[BP+SI] |

88字节包含数组、局部标量和对齐空间，不应把它直接当成数组大小；数组大小仍然是81字节。
本次布局和指令对应当前编译器、选项与源码，并不是所有编译器都会生成完全相同的代码。

## 一、两版都把二维下标换成一维偏移

数组每行9个字节，因此 tableData[i][j] 的字节偏移为 i*9+j。
i、j是从0开始的下标，输出坐标和正确乘积使用i+1、j+1。

全局版0032～003F先计算i*9+j，保存到BX，再读取_tableData[BX]。
局部版0042～004F计算相同偏移，保存到SI，再读取[BP+SI-0x56]。
包含BP的普通寻址默认使用SS；全局版的读取默认使用DS。

## 二、局部数组为什么还有数据段内容

局部版也有一份81字节初始化模板，位于_DATA，标签为L$16。
这不意味着局部变量变成了全局变量；真正被下标访问和修改的局部数组是在栈上。
函数开头执行：

```asm
MOV CX,0028H        ; 40个字
MOV AX,SS
MOV ES,AX           ; 目标段为栈段
LEA DI,[BP-56H]     ; 目标是局部数组
MOV SI,模板地址     ; 源是数据段中的初始值
REP MOVSW           ; 复制40*2=80字节
MOVSB               ; 再复制1字节，共81字节
```

MOVS从DS:SI复制到ES:DI，按照运行库的正向方向约定移动。
每次执行到这个局部定义都要形成当前调用的初始数组；本例main只被调用一次。
全局数组不需要在main开头做这次栈上复制。

## 三、数值比较

unsigned char表项读取到AL后，用XOR AH,AH零扩展为16位整数。
编译器另外计算(i+1)*(j+1)，再CMP比较两者；JE跳过正确项，只为错误项调用printf。
有符号int乘法使用IMUL，当前乘数均为1～9，所有乘积都能完整放在低16位。

## 阅读顺序

先读CHECKG_注释.txt的0032～0053，理解“算偏移、读数据、算乘积、比较”。
再看CHECKL_注释.txt的0012～0021和0042～0062，比较初始化和寻址变化。
其余循环、printf参数压栈和函数返回与此前求和、乘法表程序类似。

原始反汇编保留完整调试段；.debug_*是调试资料，不是执行代码。OBJ外部调用字段可能仍需链接修正，不能将段内偏移当成EXE的加载地址。
