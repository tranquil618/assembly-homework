# 作业 0：《hello剖析》操作步骤

依据本文件夹中的 `hello剖析.pdf`，需要完成四项实验：

1. 比较 `LEA DX,Hello` 和 `MOV DX,OFFSET Hello`。
2. 生成并阅读列表文件 `.LST`。
3. 生成交叉引用文件 `.CRF`，使用 CREF 转成 `.REF` 阅读。
4. 在 DEBUG 中直接向内存写入数据和机器码，设置寄存器并执行。

PDF 没有注明提交格式、截图数量或截止时间。下面的“记录建议”用于帮助整理实验过程，并非新增的教师要求。

## 一、准备与文件位置

两份源码已按 PDF 原文准备好：

- `D:\大三\汇编语言\ASM\HW0\LEA.ASM`：源码一，使用 `LEA DX,Hello`。
- `D:\大三\汇编语言\ASM\HW0\OFFSET.ASM`：源码二，使用 `MOV DX,OFFSET Hello`。

这两份代码保留了 PDF 的 `.MODEL SMALL` 写法，与之前测试环境用的 `ASM\HELLO.ASM` 分开。

双击课程目录中的 `START-ASM.bat`，在 DOSBox 中输入：

```bat
cd \ASM\HW0
dir
```

提示符应变为 `C:\ASM\HW0>`。如果新建文件暂时看不到，先按 `Ctrl+F4` 刷新。

以下汇编、链接、CREF 和 DEBUG 命令均在 DOSBox 中输入；源文件、LST、REF 可以用 Windows 中的 VS Code 或记事本打开。

## 二、汇编、链接并运行两份代码

依次输入：

```bat
masm LEA.ASM,LEA.OBJ,LEA.LST,LEA.CRF;
link LEA.OBJ;
cref LEA.CRF,LEA.REF;
LEA

masm OFFSET.ASM,OFFSET.OBJ,OFFSET.LST,OFFSET.CRF;
link OFFSET.OBJ;
cref OFFSET.CRF,OFFSET.REF;
OFFSET
```

MASM 的四个参数依次是“源文件、目标文件、列表文件、交叉引用文件”。逗号用于分隔参数，末尾的英文分号用于跳过后续询问。

两个程序都应输出：

```text
Hello world!
```

本次实测两份源码汇编时均为 0 Warning Errors、0 Severe Errors。链接时均有：

```text
LINK : warning L4021: no stack segment
```

原因是 PDF 原文没有定义栈段；本次按原文在 DOSBox 中运行成功。为便于对照截图，此处保留原文。今后编写完整程序时应定义栈，例如在 `.MODEL SMALL` 后增加 `.STACK 100H`，并重新汇编、链接；布局改变后，段地址也可能变化。

## 三、用 DEBUG 比较两种取地址方式

先输入：

```bat
debug LEA.EXE
```

进入 DEBUG 后，提示符为 `-`。下面只输入命令，不要把前导 `-` 当作命令的一部分：

```text
r
u cs:0 0010
t
t
t
r
d ds:dx l 0f
g
q
```

每行作用：

| 操作 | 观察内容 |
| --- | --- |
| `r` | 初始寄存器；程序刚加载时，DS 还没有指向程序的数据段 |
| `u cs:0 0010` | 反汇编入口处的程序，显示地址、机器码、指令 |
| 第一次 `t` | 执行 `MOV AX,@DATA`，把数据段地址送入 AX |
| 第二次 `t` | 执行 `MOV DS,AX`，设置 DS |
| 第三次 `t` | 执行取偏移地址指令，重点观察 DX |
| `r` | 再次查看寄存器，记录 DS、DX 和 IP |
| `d ds:dx l 0f` | 从 DS:DX 查看 0Fh，也就是 15 字节，应含 `Hello world!`、回车换行和 `$` |
| `g` | 继续执行，显示字符串并正常结束 |
| `q` | 退出 DEBUG |

随后输入 `debug OFFSET.EXE`，重复以上操作。

### 当前环境的实测对比

| 对比项 | LEA 版本 | OFFSET 版本 |
| --- | --- | --- |
| 源码 | `LEA DX,Hello` | `MOV DX,OFFSET Hello` |
| 反汇编 | `LEA DX,[0002]` | `MOV DX,0002` |
| 机器码 | `8D 16 02 00` | `BA 02 00` |
| 此条指令长度 | 4 字节 | 3 字节 |
| 执行后 DX | `0002` | `0002` |
| 执行前三条指令后的 IP | `0009` | `0008` |
| 程序输出 | `Hello world!` | `Hello world!` |

可以据此写出比较结论：本例两种写法均把 Hello 的偏移地址放入 DX，效果相同，机器编码和长度不同。

进一步理解：`LEA` 是 CPU 指令，计算有效地址，不读取该地址处的数据；`OFFSET` 是汇编器运算符，表示符号的偏移地址，最终确定的地址值可以涉及链接修正。这一行真正执行的 CPU 指令是 `MOV`。对于包含寄存器的有效地址表达式，例如 `LEA DX,[BX+SI+4]`，LEA 可以在执行时计算，而 OFFSET 不能代替这种动态计算。

上表的 3/4 字节结论只针对这里的 16 位指令形式。不要据此概括所有 LEA/MOV 的长度，或仅凭长度断言所有 CPU 上的执行速度。

## 四、查看 LST 与 REF

在 Windows 中打开：

```text
D:\大三\汇编语言\ASM\HW0\LEA.LST
D:\大三\汇编语言\ASM\HW0\OFFSET.LST
D:\大三\汇编语言\ASM\HW0\LEA.REF
D:\大三\汇编语言\ASM\HW0\OFFSET.REF
```

### LST：源码、地址和机器码的对应关系

重点看：

- `Hello DB ...` 对应的字节：`48 65 6C 6C 6F ...`。
- LEA 的指令位置是 `0005`，下一条指令从 `0009` 开始。
- MOV 的指令位置是 `0005`，下一条指令从 `0008` 开始。
- 末尾的符号表列出 `HELLO`、`START` 的类型、所属段和偏移等信息。

**LST 是汇编阶段的列表，不是程序加载后的最终内存转储。** 本次 LST 中 `HELLO` 在 `_DATA` 内为 `0000`，取地址指令的地址字段旁带 `R`；经过链接布局和地址修正，DEBUG 中看到的 DS:DX 为实际的数据段地址加 `0002`。这些数字处于不同阶段、使用不同的段基准，不要求全部一致。

### REF：符号在哪定义、在哪被使用

本次 `LEA.REF` 中：

```text
HELLO ... 3# 9
START ... 7# 14
```

- `#` 表示定义位置；普通行号表示引用位置。
- `+` 表示修改位置，若文件中存在此类记录。
- 对照 `.LST` 左侧的行号阅读：MASM 5.0 列表会因长数据展开而占据额外行，因此这里的行号可能不同于编辑器中的物理源码行号。

`.CRF` 不能当作普通文本阅读；`cref LEA.CRF,LEA.REF;` 才生成可读文本。

## 五、直接写内存和机器码

这一部分不加载 EXE，也不调用 MASM/LINK，而是手工写入机器码，让 CPU 从指定位置执行。

### 先修正 PDF 中容易出错的地方

PDF 第 2 页 A 步把 `Hello$` 放在偏移 `0000`，B 步的机器码却包含 `BA 02 00`，即 `MOV DX,0002`。在其余地址正确时，这会从第三个字符开始显示 `llo`。若数据放在 `0000`，应改成 `BA 00 00`；若保留 `BA 02 00`，则应把字符串放在偏移 `0002`。

PDF 中的 `076A`、`076B` 是演示时选用的段地址，不能认定它们在当前 DEBUG 会话中仍可用。下面使用 DEBUG 为当前被调试程序准备的区域：代码放在 `CS:0100`，数据放在 `DS:0200`。段值采用你刚进入 DEBUG 时读到的值。

### 1. 启动一个全新的 DEBUG 会话

若还在前一个 DEBUG 中，先 `q` 退出，然后在 DOSBox 中输入：

```bat
debug
```

注意这次没有文件名。然后输入：

```text
r
```

记录 CS 和 DS。本机此次实测两者均为 `0727`；你的值可能不同。以下完整示例假设它们均为 `0727`。**所有示例中的 `0727`，以及机器码里对应的 `27 07`，都必须按你的实际值替换。**

例如，实际值为 `0750` 时，机器码中使用 `50 07`。这是 8086 的小端存储：16 位数值先写低字节，再写高字节。

这里应看到 CS=DS；若你看到两者不同，先退出并按上述方式重新运行不带文件名的 `debug`。

### 2. 写入字符串

输入：

```text
e ds:0200 48 65 6c 6c 6f 24
d ds:0200 l 6
```

右侧应看到 `Hello$`。`$` 是 DOS 09H 功能的结束标记，不会被输出。

### 3. 写入 17 字节机器码

**以下一行仅适用于刚才 CS=DS=0727 的情况；否则先替换 `27 07`：**

```text
e cs:0100 b8 27 07 8e d8 ba 00 02 b4 09 cd 21 b8 00 4c cd 21
u cs:0100 0110
```

对应关系是：

| 字节 | 指令 | 作用 |
| --- | --- | --- |
| `B8 27 07` | `MOV AX,0727` | 把本次选用的数据段地址放进 AX |
| `8E D8` | `MOV DS,AX` | 设置 DS |
| `BA 00 02` | `MOV DX,0200` | 指向刚写入的字符串 |
| `B4 09` | `MOV AH,09` | 选择 DOS 字符串输出功能 |
| `CD 21` | `INT 21H` | 输出 DS:DX 指向的字符串 |
| `B8 00 4C` | `MOV AX,4C00H` | 选择退出功能、返回码 0 |
| `CD 21` | `INT 21H` | 正常退出程序 |

代码位于 `0100`～`0110`，数据位于 `0200`～`0205`，所以即使 CS=DS，它们也不会重叠。

### 4. 设置寄存器并运行

下面每一行输入后都按回车；输入 `r cs` 等命令后，DEBUG 会先显示旧值并等待你输入新值。`0727` 仍需替换为本次实际段值。

```text
r cs
0727
r ds
0727
r ip
0100
r
g
q
```

这里重新填写 CS/DS 是为了对应 PDF 的寄存器设置步骤，填写的是刚才记录的原值。**IP 必须与代码写入的起点一致，本方案为 `0100`，不能照抄 PDF 的 `0000`。**

预期输出：

```text
Hello
Program terminated normally (0000)
```

本次已用以上 17 字节机器码实际完成验证。`CHECK\MEM.IN` 是验证时段值固定为 `0727` 的输入记录，不应跨会话直接重放；请按你当前的寄存器值完成上述步骤。
