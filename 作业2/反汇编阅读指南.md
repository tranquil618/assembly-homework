# 求和程序反汇编阅读指南

先读 `SUMC_注释.txt`，再读 `SUMNC_注释.txt`。这两份文件保留原来的地址、机器码、C 源码和全部段内容，并在代码指令后追加中文解释。
原始 `SUMC.DIS`、`SUMNC.DIS` 未修改。中文注释文件使用 UTF-8，可直接在编辑器中打开，不需要用 GBK。

## 第一遍只读固定求和版的循环

不必一次理解所有机器码和函数准备工作。先在 SUMC_注释.txt 中找到下面三件事：

1. sum 在哪里？在 `[BP-2]`。
2. i 在哪里？在 `[BP-4]`。
3. 循环为什么会重复？执行完 i++，跳回比较位置。

这份程序的循环可整理成如下等价形式（为了阅读省略机器码，简化内存写法）：

```asm
MOV WORD PTR [BP-2], 0     ; sum = 0
MOV WORD PTR [BP-4], 1     ; i = 1

判断:
    CMP WORD PTR [BP-4], 100
    JG 输出               ; i > 100 就离开循环

    MOV AX, [BP-4]        ; AX = i
    ADD [BP-2], AX        ; sum += i

    ; 原始反汇编此处还读取了一次 i 的旧值，未优化代码保留了这个动作
    INC WORD PTR [BP-4]   ; i++
    JMP 判断
```

上面是辅助理解的整理，不是直接复制的完整原始反汇编。真正的代码和地址以注释版为准。

先用纸笔跟踪前三次：

| 进入本轮时 i | 原来的 sum | 执行 sum += i 后 | 执行 i++ 后 |
| --- | --- | --- | --- |
| 1 | 0 | 1 | 2 |
| 2 | 1 | 3 | 3 |
| 3 | 3 | 6 | 4 |

当 i=100 时还会执行一次累加；i 加到 101 后，JG 才跳到输出位置。所以 100 被计入，101 不计入。
C 的 for 不一定编译为 LOOP。本次使用 CMP、JG、INC 和 JMP，功能仍是循环。

## 再看 BP、SP 与方括号

`MOV AX, BX` 复制寄存器的数值。
`MOV AX, [BP-4]` 从内存读取变量的数值。
`LEA AX, [BP-4]` 取得该位置的偏移地址，不读取其中的值。

`BP-4` 是地址计算，不是“让变量减去 4”。
例如 BP 假设为 1000H，`[BP-4]` 就指向栈段中偏移 0FFCH 的内存。

8086 的 16 位 PUSH 通常使 SP 减 2，POP 使 SP 加 2；因此保存数据时，栈向较低的偏移地址扩展。
SP 随压栈和出栈变化。函数建立 BP 后，可以在本函数中持续用它定位变量。

SUMC 的布局是：

```text
[BP]       保存的旧 BP
[BP-2]     sum（2 字节）
[BP-4]     i（2 字节）
[BP-6]     返回值暂存区（2 字节）
```

SUMNC 多了 n，布局变为：

```text
[BP]       保存的旧 BP
[BP-2]     sum
[BP-4]     i
[BP-6]     n
[BP-8]     返回值暂存区
```

这也解释了前者 `SUB SP,6`，后者 `SUB SP,8`。布局是这次编译的结果，换编译器或选项后可能改变。
`WORD PTR` 告诉汇编器此处是一个 16 位内存操作，尤其当立即数和内存地址本身不能确定操作大小时需要它。

## printf 为什么前后有 PUSH 和 ADD SP

以 `printf("%d\n", sum)` 为例，本次调用把参数从右到左压栈：

```asm
MOV AX, [BP-2]        ; 取 sum 的值
PUSH AX               ; 第二个参数 sum
MOV AX, 格式字符串地址
PUSH AX               ; 第一个参数 "%d\n" 的地址
CALL printf_
ADD SP, 4             ; 释放两个 2 字节参数
```

CALL 会另外压入返回地址，printf 用 RET 返回后，这个返回地址已经被取走。
调用者还要清理自己压入的参数，所以有 ADD SP,4。
这条 ADD 改的是栈顶位置，不改变 sum，也不是多输出四个字符。

printf 的十进制转换在运行库内部完成。这里看到的是传参数和调用；不必在 main 中寻找你手写 ASM 的除以 10、逐位输出循环。
C 的字符串以零字节结束；它们不使用 DOS INT 21H/09H 的 $ 结束标记。

## 最后读输入版增加的内容

SUMNC 的求和循环与 SUMC 相同，只把固定上限 100 换成内存中的 n。
新增部分按以下顺序阅读：

1. 打印提示字符串。
2. `LEA AX,[BP-6]` 取得 n 的地址，作为 scanf 的 &n 参数。
3. 调用 scanf，输入的数值写入 n，成功读取的项目数放在 AX。
4. 比较 AX 和 1：读入失败就显示 Invalid input，准备返回 1。
5. 比较 n 和 1、100：范围错误就提示并准备返回 1。
6. 输入合法，i=1，开始求和。

务必区分：scanf 返回后，AX 中的 1 不是 n=1，而是“成功读取了一个项目”。n 在 [BP-6] 中。

范围检查对应 `n<1 || n>100`。先检查 n<1；已经成立就直接报错，不必继续检查 n>100，这叫短路求值。

你的 `while(1)` 中，错误路径 return，成功路径 break，因此不存在需要执行第二轮的路径；本次反汇编没有回到输入处的循环跳转是合理的。

## return 与程序退出

本次编译器先把 main 的返回值保存到一个栈槽，再在公共收尾处取到 AX。
错误路径放 1，正常路径放 0。
之后恢复 SP、BP 和保存过的寄存器，执行 RET，返回 C 运行库。

这与你的手写 ASM 最后直接用 `MOV AX,4C00H / INT 21H` 不同：C 的 main 返回后，由运行库完成后续退出工作。

## 可以暂时跳过的部分

- 左侧机器码：先认识它存在即可，不必背诵。
- __STK 的内部实现：先知道是运行库栈检查即可。
- CONST 后的字符串字节转储：只需能对应到提示文字和格式字符串。
- .debug_*：保存调试信息，不是要执行的汇编代码。其 USE32 标记不代表主程序是 32 位，代码段是 _TEXT USE16。

这些是 OBJ 反汇编：外部函数 CALL 的地址字段可能仍为待链接修正的占位值，L$ 标签也是反汇编器生成的名字。
不能把 OBJ 中的地址直接当成 EXE 加载后的地址。
